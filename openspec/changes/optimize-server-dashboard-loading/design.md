# Design

## Context

См. proposal.md. `server.html` начинает `/check` и `/stats` параллельно, но первый вызов `/connections` находится в продолжении `/check`. `app.py` объединяет менеджеры запросов и фоновых задач через SSH-пул. Запись `data.json` атомарна, однако атомарность файла сама по себе не защищает от записи ранее прочитанного снимка.

## Goals / Non-Goals

**Goals**

- Сократить критический путь до списка подключений и количество удалённых команд на открытие страницы.
- Сохранить совместимость текущих маршрутов, ролей, поддерживаемых SSH-окружений и постоянных данных.
- Отделить наблюдение для интерфейса от сверки и операций жизненного цикла.

**Non-Goals**

- Кеширование клиентских конфигураций, ключей и полного ответа списка peers.
- Постоянное хранилище кеша, изменения развёртывания и переработка механизма восстановления peer.

## Decisions

1. **Независимое отображение.** Серверный шаблон получает разрешённые сведения о сохранённых экземплярах и использует их для первоначального выбора. Первый список идёт отдельным запросом. Результат живой проверки уточняет выбор, не перезагружая его при совпадении. Переиспользовать защиту от устаревших ответов, добавить контроль поколения загрузки и сохранить polling, ручное обновление и редактор. Smart Route обновляет свой статус отдельно. Последовательная загрузка проще, но добавляет весь обход протоколов к задержке списка.
2. **Ограниченный кеш в памяти процесса.** Два вида снимков по UID и актуальной идентичности цели. Сводка свежая 15 секунд, статус протоколов свежий 30 секунд, срок показа устаревшего снимка до 5 минут от последнего успеха. Эти значения являются начальными бюджетами. Страница получает последний статус без SSH в обработчике HTML. Полная проверка обновляет отображаемый снимок после успешного наблюдения и сверки. При истечении TTL фронтенд инициирует обновление. Явный `/check` выполняет живую проверку, совместимые вызовы `/stats` сохраняют тело ответа, метаданные свежести можно передать заголовками. Только безопасная для интерфейса проекция попадает в кеш. Проверка прав и разрешение UID предшествуют выдаче. Объединять сбор по виду и ключу, ограничить объём и срок жизни, не держать общий lock во время SSH. Отмена одного ожидающего не отменяет сбор для остальных. После изменения использовать поколение снимка для отбрасывания запоздалых результатов. Использовать существующие точки удаления, смены SSH-реквизитов, восстановления состояния и изменения протокола. Кеширование целого `/check` смешивает наблюдения и побочные эффекты. Внешний кеш добавил бы зависимость для локального развёртывания.
3. **Сокращение удалённой работы.** Объединить CPU, RAM, диск, сеть, uptime и IPv6 в один удалённый вызов с секциями и независимыми значениями по умолчанию. Обозначить отсутствие или ошибку чтения счётчиков AWG отдельным значением. Успешный пустой объект считать валидным. Параллельные отдельные команды на общем SSH-пуле сохраняют количество удалённых запросов и конкуренцию за транспорт.
4. **Бюджет SSH.** Использовать монотонный дедлайн на открытие канала, подтверждение exec, передачу stdin, чтение обеих очередей и exit status. Закрывать просроченный канал, чтобы прервать ожидание подтверждения, и проверить завершение вспомогательного ожидания. Сохранить порядок блокировок и обработку неопределённости записи. Повтор после возможного запуска команды разрешать только там, где повтор уже безопасен по контракту, и внутри оставшегося бюджета. Сам таймаут канала Paramiko не ограничивает ожидание статуса.
5. **Условное слияние наблюдений.** Собирать удалённые результаты без блокировки файла. В короткой секции под существующей дисциплиной `DATA_LOCK` и `STATE_FILE_LOCK` перечитывать данные, проверять UID, идентичность цели и исходное состояние затрагиваемых экземпляров, применять только актуальные поля. Сохранить динамические экземпляры, exit-связи, ошибки отдельных проверок и recovery generation. При конфликте отбрасывать затронутое наблюдение, не писать прежний снимок и не публиковать его как свежий. Блокировка на весь SSH-обход увеличила бы задержку записи и загрузки.

## Risks / Trade-offs

- Устаревший снимок может показать уже остановленный экземпляр → отметить свежесть, перепроверять удалённо и не использовать снимок для доступа и действий.
- Общий дедлайн затрагивает длительные команды → сохранить отдельные бюджеты существующих вызывающих путей и проверить интерактивный ввод, большой вывод, сетевую ошибку и fence жизненного цикла.
- Кеш ограничен процессом и пуст после перезапуска → оптимизировать холодный путь независимо и измерить его отдельно. Межпроцессное объединение запросов вне области.
- Ошибка отдельной метрики отличается от сбоя SSH → сохранить допустимые частичные данные, не кешировать ошибку транспорта как свежую сводку.

## Migration Plan

Внедрять этапами по tasks.md. Перезапуск сбрасывает кеш, миграция состояния не требуется. Откат отдельных коммитов сохраняет формат постоянных данных. Сравнить до и после на детерминированной задержке SSH и в браузере. Рабочий сервер измерять только в отдельно согласованном окружении.
