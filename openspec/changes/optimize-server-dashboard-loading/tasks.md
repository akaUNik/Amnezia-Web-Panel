## 3. SSH и сверка состояния

- [ ] 3.1 Ограничить жизненный цикл SSH-канала общим бюджетом, дренировать оба потока и завершать канал при таймауте. Тестами подставного транспорта проверить заполненное окно, отсутствие exec ACK и exit status, stdin, освобождение блокировок и отсутствие зависшего ожидания.
- [ ] 3.2 Сохранить контракт ошибок, защитное ограждение и допустимые повторы SSH-команд. Запустить целевые тесты гонок транспорта, cooldown и жизненного цикла peer. Отдельно проверить, что неоднозначная удалённая запись не повторяется вслепую.

Тестами с барьерами проверить параллельное назначение, переупорядочивание, редактирование и удаление сервера, изменение протокола и восстановление. Покрыть сохранение динамических экземпляров и exit-связей при неполном результате.

## Workflow follow-up

- Перед началом apply привязать change к GitHub Issue, синхронизировать `develop` с `origin/develop` и использовать ветку `fix/<issue>-server-dashboard-loading`. Сохранить существующие локальные файлы скиллов отдельно от change.
- Оформлять атомарные conventional commits и один PR в `develop` с `Closes #<issue>`. Объединять через merge commit после ревью и проверок. Если GitHub не закроет issue при слиянии в `develop`, закрыть его после merge.
