# Proposal

## Why

Основным репозиторием выбран `akaUNik/Amnezia-Web-Panel` на GitHub. Существующие workflows уже собирают приложение, но публикация не зависит от тестов, инструкции установки ведут к чужим образам, а проверка новых версий обращается к релизам `PRVTPRO`.

## What Changes

- Настроить GitHub Actions в `akaUNik/Amnezia-Web-Panel`: проверки pull request, сборки main и тегов `v*`, ручная проверка сборки; публикация только после успешных проверок того же коммита.
- Сохранить полную текущую матрицу: бинарники Linux и Windows (macOS исключена по уточнению пользователя); обычный Docker `linux/amd64,linux/arm64`; WARP Docker `linux/amd64`.
- Хранить результаты сборок в Actions artifacts с явно заданным сроком 30 дней; для версионных тегов публиковать полный комплект бинарников, checksums и сведений о сборке в GitHub Releases этого репозитория.
- Публиковать контейнеры в связанном с репозиторием GHCR-пакете `ghcr.io/akaunik/amnezia-panel`, согласовать README и Compose с этим источником, сохранить возможность локальной WARP-сборки.
- Проверять новую версию по опубликованному стабильному релизу `akaUNik/Amnezia-Web-Panel`, корректно сравнивать версии и различать отсутствие релиза и недоступность проверки. Ссылки скачивания направлять в этот же репозиторий.
- Проверять соответствие версии приложения релизному тегу до публикации; предварительные версии не предлагать как стабильные обновления.
- По уточнению пользователя перенести зависимости в uv-проект: `pyproject.toml`, `uv.lock`, разделённые runtime/dev/build группы, locked-установка в CI и Docker вместо `requirements.txt`.
- Описать хранение, скачивание, публикацию и повторный запуск; подтвердить результат реальным запуском Actions и скачиванием файлов/образов обратно.

## Capabilities

### New Capabilities

- `build-pipeline`: проверка и сборка поддерживаемых вариантов в GitHub Actions с зависимостями публикации от проверок.
- `release-distribution`: хранение файлов сборок и релизов, публикация связанных GHCR-образов и использование собственных артефактов при установке.
- `update-checking`: проверка доступной стабильной версии в основном GitHub-репозитории и достоверное отображение результата в настройках.

### Modified Capabilities

Нет: `openspec list --specs` не обнаружил существующих спецификаций.

## Impact

Затрагиваются `.github/workflows/build.yml`, `.github/workflows/test.yml`, небольшие helpers публикации/проверки версии в `scripts/ci/`, `templates/settings.html`, используемые им JS-ресурсы, передача констант проекта в `app.py`, переводы, тесты, README и Compose-файлы. Сохраняются Dockerfiles, ресурсы PyInstaller и существующие проверки unittest/Chromium/root с изолированным состоянием.

Публичность репозитория и default branch `main` подтверждены через GitHub CLI. Нужны включённые Actions, права `GITHUB_TOKEN` на releases/packages и публичный доступ к GHCR-пакету; настройки Actions/пакета ещё не проверены. GHCR хранит контейнеры в пакете владельца, связанном с репозиторием, а не в Git-дереве.

Вне области: автоматическая установка обновлений, перенос старых релизов, публикация на Docker Hub/GitVerse, изменение VPN-функций, массовая замена исторических/upstream-ссылок и перенос загрузки RKN-скриптов. Change содержит только плановые артефакты; реализация начинается отдельным apply.
