# Proposal

## Why

При установке AmneziaWG 3.1 панель предложила повторить попытку, когда в окне установки отображалось «Building container...». Это же сообщение получают два разных запроса: один ещё ждёт доступа к серверным операциям, другой уже выполняет установку и может завершиться успешно после ответа браузеру.

## What Changes

- Дать принятому запросу установки дождаться результата установщика, включая длительную сборку Docker. Сохранить ограниченное ожидание допуска для конкурирующих запросов.
- Показывать администратору, когда установку отклонили до запуска, когда требуется восстановление после неопределённого результата SSH и когда установщик вернул конкретную ошибку.
- Показывать ожидание результата без имитации этапов. Если ответ потерян, сообщать, что результат неизвестен и перед повторной попыткой требуется проверить состояние сервера.

## Capabilities

### New Capabilities

- `protocol-installation` — допуск установки протокола на управляемый сервер и отображение её результата в панели.

### Modified Capabilities

## Impact

Изменение касается общего маршрута установки в `app.py`, окна установки в `templates/server.html`, переводов и регрессионных тестов. AmneziaWG 3.1 (`awg3`) служит контрольным случаем для всех протоколов, использующих этот маршрут. Формат запроса и успешного ответа сохраняется. Задача [#40](https://github.com/akaUNik/Amnezia-Web-Panel/issues/40).
